# カード図鑑：SP比較モード（試験実装）

対象は `card-catalog.html`。初期表示の「詳細」と既存の所持・育成編集を維持し、「SP」のみ追加する。ステータス・Active・Passive表示モードは未実装のため選択不可。既存のタレント・Passiveスキル・文字検索・レアリティ・タイプ絞り込みは両モード共通で、切替時に保持する。

## データと表示

Canonicalの既存Runtime投影 `data/runtime-cards.json` を既存adapterで読み込む。生成器、Canonical、Runtime、計算エンジン、保存形式は変更しない。

| 列 | 取得元・表示単位 |
| --- | --- |
| Thumb | 既存CardImageResolverのcandidatesからkind=thumbのみ。未登録・失敗時は画像なし。Thin/Fullのリクエストなし |
| カード／タレント | card.name / card.member.name |
| 効果時間 | skills.special.levels[].raw.effectDurationMillisecondを秒表示 |
| 効果量 | effects[].effect.raw.type=SCORE_UP_EFFECT_UP_PERMIL_UPのvalue（‰→%）。スコアサポートの効果量であり、スコア全体の倍率ではない |
| 発動率UP（%） | LIVE_ACTIVE_SKILL_ACTIVATION_PROBABILITY_UP_PERMIL_UP。既存ActivationProbabilityEngine.fromScheduleの単位変換を利用し、rateを%表示。SP自体の発動確率ではなくActive発動率への補正 |
| ライフ回復 | LIFE_RECOVERYのraw.valueを数値表示 |
| 判定強化 | JUDGEMENT_ENHANCEのeffect.description。実データに数値がないため説明文のみ、数値ソートなし |

上記のtypeには共通接頭辞 `LiveActiveSkillEffectType_LIVE_ACTIVE_SKILL_EFFECT_TYPE_` が付く。条件はcondition.descriptionを併記し、成立判定しない。既知の装飾タグは既存skillDescriptionTextで除去し、全項目をtextContentで出力する。

複数効果は原データ順ですべて表示する。数値列は昇順／降順に対応し、複数値の場合は表示順の辞書式比較、同値は従来のカード順を維持。「—」は両方向で末尾。未知の効果は計算せずカード情報欄に未対応として表示する。推測値は補完しない。

## 育成状態

SPレベルは既存 `canonicalBloomLevels(card, opening).special` で選択する。初期値は開花0、最大育成は開花5、保存状態はカードごとの既存保存値（未保存は既存仕様どおり0）。カスタムはSPに関係する開花の初期／保存／最大を指定する。特訓はSPに影響しないため項目を設けない。

全表示カードに同じモードを適用するが、保存値はカード別。変更時に表示と現在のソートを更新し、保存データを書き換えない。編成内のSP適用・条件・リーダー等を計算する画面ではない。

## レイアウト・画像

1カード1行、カード名とタレント名を上下に表示。左2列を横方向、見出しを縦方向に固定。表領域内で縦横スクロールし、狭幅ではカード列を小さくする。Thumbは2行程度の高さ（PC48px、狭幅40px）で正方形・contain表示、欠損時も枠を維持。画像取得元・Worker設定と認証は既存resolverに従う。

## 検証

`python3 tests/verify-catalog-sp.py` は全201枚・402レベル、単位、条件、開花、複数効果、未知／欠損、ソート、データ不変を検証する。実データの効果エントリーはスコアサポート402、発動率UP94、ライフ回復46、判定強化44。これらはカード数ではなく両レベル合計。現在の未知効果は0。

`python3 tests/verify-parameter-comparison-browser.py --page catalog-sp-browser.html` は隔離Chromeで1280/768/390px、モード・育成・保存不変・既存絞り込み・ソート・固定列／見出し・画像成功／欠損を検証する。画像成功はローカルモックを使い、実Worker認証成功を意味しない。

今後の課題は実環境での操作感確認と、追加される未知効果の表示対応。今回SP・Activeの新たな検索条件や、既存エンジンの対応範囲拡張は行わない。

## SP表UIの調整（2026-11-01）

画像列の見出し文字と各カードのSPレベル表示を省略。ソートはキーボード操作可能なbuttonを保ち、背景・枠・影のないテキスト見出しとする。カード名は太字、タレント名は通常文字。表幅1020px、名前列300px（狭幅180px）、数値列80〜140px、セル余白6px。固定列・見出し、数値ソート、育成プレビューは維持する。

名前見出しで所属・期生順を切り替える。昇順は既存sortCatalogCardsForDisplayを再利用。降順は所属ブロックだけを反転し、同一期生内のタレント順・同一タレントのカード順を保持する。所属はHOLO_MEMBERSの先頭登録所属を使用（フブキは1期生、ゲーマーズの順なので1期生に配置）。未確認所属は推測せず末尾。独自の所属順位表は作成しない。

## ページスクロール型の高密度表（2026-11-01）

この節は以前の70vhスクロール枠・1020px固定幅・48px画像の仕様を置き換える。

- SP時のみmainの最大幅を解除。検索パネルと育成・説明の最大幅は従来値を保ち、操作領域の配置を変更しない。詳細時は従来の1180px上限へ戻す。
- 表は幅100%、読みやすさの下限614px。画像40px列、名前は残余幅、時間64px・効果量104px・発動率104px・回復64px、判定強化20%（狭幅110px）。狭幅の名前は128px。余白を画像列へ配分しない。
- Thumb32px、本文12px、条件文10px、セル余白上下3px・左右4px。数値は右揃え。カード名は太字、タレント名は通常文字。
- 表の高さは内容依存。最大高さを設けず、表内の縦スクロールは発生させない。横方向だけ必要時にスクロールする。
- ページスクロールで元の見出しがサイトナビ下端を越えたとき、表示専用の見出しをfixedで表示する。元のthの実寸・横スクロール位置を同期し、ボタン操作は既存ソートボタンへ委譲する。表の末尾・詳細モードでは非表示。見出しの固定は縦スクロールボックスを必要としない。
- サイトナビは既存設定を維持し、見出しのtopはその実測下端、z-indexは40（サイトナビ50より下）。画像列の実幅を名前列のstickyオフセットに使う。

高さ900px・93枚のブラウザ測定では、1280/768/390pxの表幅は1212/716/614px、横スクロール距離は0/0/276px、固定列合計は約634/237/168px。表をスクロールして読む位置で完全に入る行数は19/19/14行（カード名の折り返し・条件文・位置により変動）。最初の行高は39/39/約54px。上部操作領域を維持しているため、ページ最上部での見える行数とは異なる。

テストはページスクロール、表内縦移動不可、横同期、固定見出し経由ソート、画面幅、詳細復帰を検証する。仮想時間iframeテストではページscrollイベントを明示送出する。通常ページの実時間スクロールも別途検証する。

検証結果：SPブラウザ検証およびtests/verify.pyは成功。通常Chromeページでもネイティブな縦横スクロールで同期し、見出し上端99px＝サイトナビ下端99px、表内縦スクロール量0を3幅すべてで確認。検索パネル内の入力・選択・ボタンを含む矩形は詳細→SP切替前後で一致し、詳細復帰時の1180px上限も一致した。

初回の仮想時間iframe検証ではscrollイベントの配送が遅れ、見出し表示チェックが失敗した。イベント明示送出と実時間Chrome検証で切り分け、正常動作を確認。実時間検証ツールも初回はChrome内部タブへ誤接続したため失敗し、通常ページを選択する修正後に成功した。

既存ブラウザ一式は7件成功、旧ライブラリ件数を期待する5件（unit-card-picker、talent-filter、catalog-passive-filter、card-display-order、card-export）が従来どおり失敗。これらの期待値は変更していない。実Worker認証は今回の検証対象外で、画像はローカルモックによる成功・欠損検証。

## ステータス比較とテーブルUIの共用（2026-11-02）

「ステータス」を有効化。Thumb／カード名・タレント名／P／T／S／TOTALの6列を表示する。初期表示は従来どおり詳細。SP・ステータスそれぞれの育成・ソート状態はモード切替で保持し、検索・タレント・Passiveスキル・レアリティ・タイプは共通条件として適用する。

`catalog-comparison-table.js`に画像、行・セル描画、育成操作、数値ソート操作、ページスクロール型固定見出し、固定列を集約。従来CSSクラス／data属性は互換性のため維持する。`catalog-comparison-order.js`には従来の数値比較・所属順処理を移し、SPからの既存APIも維持。SP固有の効果解析は`catalog-sp-data.js`、ステータスは`catalog-status-data.js`に分離。各tableファイルは列・説明・計算呼び出しを指定する薄い構成定義。

ステータスは既存`calculateCardParameters(card, training, opening)`を呼び出す。初期＝特訓0／開花0、最大＝特訓4／開花5、保存＝各カードの保存値（未保存は既存の0）。各特訓段階のLv上限を使う点も詳細と同じで、Lv1値を新たに推定しない。カスタムでは開花・特訓それぞれに初期／保存／最大を指定する。TOTALは既存計算結果のP＋T＋S。Passive・Leader・Memory・Board・衣装・編成相互作用は含まない。保存値は変更しない。欠損データは推測せず「—」とエラー概要を表示する。

表示は既存の32px画像・12px本文・ページ縦スクロールを維持。ステータス表の下限幅は424px、数値列は通常14%、狭幅64px。1280／768pxでは横スクロールなし、390pxでは86px。SP表の列幅・表示値は従来どおり。

検証：全201枚×特訓5段階×開花6段階＝6030通りが詳細の既存adapterと一致し、TOTAL合計も一致。全育成モード・カスタム9組・欠損・読み取り専用性を検証。ブラウザは3画面幅で全レアリティの値、昇降順、共通フィルター、モード切替、固定見出し／列、詳細復帰を検証。SPの初回ブラウザテストは非表示のステータス育成コントロールを誤選択して失敗したため、操作対象をSP領域内へ限定し、再実行で成功。計算条件や期待値の緩和は行っていない。

既存ブラウザの旧カード件数を期待する5件は引き続き失敗し、この作業では期待値を変更しない。

## Passive原文と共通ソート初期方向

ステータス表のTOTALの右にPassive列を追加。CanonicalのLangGeneratedLivePassiveSkillLevel_Jpnのtextを保持するRuntimeの`skills.passive.levels[].description`を全文表示する。既存`canonicalBloomLevels(card, opening).passive`で表示レベルを選択し、特訓はPassiveレベルを変えない。効果の断片から文章を組み立てず、装飾タグ・改行もそのままtextContentで表示する。HTMLとして解釈せず、原文が存在しない場合は「—」。数値計算が不可能でも、取得可能な原文は独立して表示する。

Passive列は320px・折り返し可・中央揃え。表の最小幅744px、P/T/S/TOTALは各64pxを維持。1280/768/390pxで表幅1212/744/744px、横スクロール0/28/406pxを実測。既存の固定列・固定見出し・ページ縦スクロール方式は維持する。

SP・ステータス共通の列クリックは初回降順、2回目昇順、以後交互。別の列を選んだときも降順から開始する。数値比較・欠損値末尾・同値時の安定順・所属ブロックの定義は変更しない。

検証：201枚×30育成状態で、Passiveのレベル・全文がCanonicalの言語factと一致。402レベルの実データは各1効果参照。複数効果を含む合成原文でも全文・改行・タグが保持され、Passiveなしは空の表示データになることを確認。既存SP／ステータス／中央揃えのブラウザテストは今回の降順仕様に期待値を更新し、3画面幅で確認する。

### Passive表示の装飾タグ除去

表示時のみ既存skillDescriptionTextを使用し、attribute（cute/happy/pure等）およびhighlightの開閉タグを除去する。内部テキスト、効果全文、改行は維持し、textContentによる安全な表示を継続する。Canonical・Runtimeの原文は変更しない。上記の「タグもそのまま表示」の記述はこの表示仕様で置き換える。
